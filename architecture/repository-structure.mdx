The katbose.dev repository is a pnpm workspace monorepo. It uses Node 24, pnpm 11, strict TypeScript, and exact package versions with a committed lockfile. This page maps the top-level layout and the internal structure of the web application.

## Top-level tree

```text
katbose-portfolio/
├── apps/
│   ├── web/                  # Next.js public site → Cloudflare Workers via OpenNext
│   ├── cms/                  # planned Phase 2: Payload CMS → Render
│   └── dashboard/            # planned Phase 5: private analytics dashboard
├── packages/
│   ├── shared/               # shared types, Zod schemas, constants, utils
│   └── katbose-card/         # integrated source for the published `katbose` package
├── supabase/                 # migrations, local config and pgTAP security tests
├── scripts/                  # backup-set contracts and restore tooling
├── e2e/                      # Playwright specs
├── .github/workflows/        # CI, migration, secret scan and weekly backup
├── docs/                     # 20-part specification (01–20)
├── render.yaml               # planned Phase 2 Render blueprint
├── pnpm-workspace.yaml
└── PLAN.md
```

## Directory reference

| Path | Contents |
| --- | --- |
| `apps/web` | Next.js 16 public site deployed to Cloudflare Workers via OpenNext |
| `apps/cms` | Planned Phase 2: Payload CMS on Render |
| `apps/dashboard` | Planned Phase 5: private analytics dashboard on Render |
| `packages/shared` | Shared Zod schemas, types, and constants used by multiple apps |
| `packages/katbose-card` | Source for the published `katbose` npm CLI package |
| `supabase/` | Migrations, local config, and pgTAP security tests |
| `scripts/` | Backup scripts, restore tooling, and later-phase content export utilities |
| `e2e/` | Playwright end-to-end specs |
| `.github/workflows/` | CI, production migration, secret scanning, and weekly backup workflows |
| `docs/` | Architecture and specification documents (01 through 20) |
| `render.yaml` | Render blueprint for Phase 2 (no secret values committed) |

<Warning>
  `apps/cms` and `apps/dashboard` directories are not present in the repository yet. They are planned for Phase 2 and Phase 5 respectively.
</Warning>

## Shared package rule

Anything used by two or more apps (Zod schemas, content types, constants like rate-limit values) lives in `packages/shared` so the CMS and web app cannot drift apart. The web app imports from `@katbose/shared`, and the planned CMS app will use the same schemas for validation and types.
